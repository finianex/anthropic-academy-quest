# Anthropic Academy 學習地圖

把 [Anthropic Academy](https://anthropic.skilljar.com/) 的 20 門課做成一個遊戲化的繁體中文學習系統：世界地圖上有五座島，帶著自己的角色一路走完，讀完一堂拿 XP、升等、解徽章、換裝備。

> 非官方學習站，與 Anthropic 無隸屬關係。本站內容是讀過官方課程後理解重寫的原創繁中整理，不重製、不逐字翻譯官方教材。影片、測驗與結業證書一律以官方 Skilljar 平台為準。

姊妹專案（純閱讀版）：[anthropic-academy-zh-tw](https://github.com/finianex/anthropic-academy-zh-tw)

## 現在做到哪

**Phase 1 完成** —— 不需要登入就完整可玩，進度存在瀏覽器裡。

- 世界地圖：五座島、進度環、島與島之間的建議航線
- 島嶼路徑：多林果式蜿蜒路徑，一門課一段，角色站在你最後造訪的節點上
- **課堂：短教學 → 練習**。3 張可跳過的教學卡，然後 7–11 題練習。答錯會重排到後面，答對一次才出隊——所以一場練習必然以「每一題都答對過」結束
- **跨課程複習**：每個題目記熟練度（0–5 階），到期就從你學過的所有課裡混合出題
- XP／等級（8 階）、12 枚成就徽章、6 種身形 × 5 色 × 4 個配件槽
- 我的筆記：每堂一篇，自動儲存，可在「我的角色」頁總覽與匯出

**Phase 2（未開始）** Google 登入 + Firestore 同步。目前進度只存在這台裝置。

## 學習迴圈

目標是**學習**，不是閱讀。所以「讀完」不算過關，把練習做完才算。

一堂課的題目全部從筆記結構推導，**不編造任何內容**——正解是資料裡本來就有的事實：

| 題型 | 正解來自 | 干擾項來自 |
|---|---|---|
| 選擇（概念名 → 說明） | `concepts[i][1]` | 同一堂的其他概念，其次同一門課 |
| 選擇（說明 → 概念名） | `concepts[i][0]` | 同上 |
| 配對 | `concepts` 的 [標題, 說明] 配對 | 不需要 |
| 排序 | `workflow` 的陣列順序 | 不需要 |
| 誤區辨識 | `pitfalls` 的其中一項 | 同一堂的 `workflow` 步驟 |

實測 154 堂全部出得了題：**每堂 7–11 題、平均 8.82 題，全站 1,358 題**，且每一題都通過驗證（選擇題恰好 4 個不重複選項、恰好 1 個正解）。

干擾項優先取自**同一堂課的其他概念**，因為真正的學習目標就是分辨這一課的 A 概念和 B 概念。從別的課抓來的干擾項太好排除，題目會退化成「哪一個看起來跟這一課有關」。

誤區辨識題的方向會**隨機翻轉**（有時問「哪個是誤區」，有時問「哪個是建議做法」）。因為誤區和流程的句子風格不同——一個描述錯誤、一個是指令——方向固定的話靠語氣就能猜對。

**沒有克漏字題**：實測 742 個概念裡只有 5 個的標題出現在自己的說明文字中，無法可靠地挖空關鍵詞。與其用啟發式亂挖，不如不做。

### 文字標準

課文要「快速看懂」，所以有明確的可量測標準，不是憑感覺寫：

| 欄位 | 上限 | 理由 |
|---|---|---|
| `tldr` | 一句、≤40 字 | 整堂課最先看到的一行 |
| `overview` | 2–3 短句 | |
| `concepts[i][1]` | ≤50 字、一句話 | **它會直接變成選擇題的選項** |
| `concepts[i][2]` | 清單（選填） | 列舉不要塞成句子 |
| `workflow[]` | 每步 ≤22 字、動詞開頭 | |
| `pitfalls[]` | 每項 ≤28 字 | |

另外三條規則：

- **去書面語**：以／而／並／該／使／之／則／於 一律換成白話。
- **列舉一定要用清單**，不能用「、」和括號硬塞成一個句子。改版前最長的一句是
  274 字，內容其實是六個 slash command 各配一段括號說明——那不是句子寫壞了，
  是結構用錯了。
- **刪掉與學習無關的內容**：研究出處、機構與教授姓名、「課文列出」這類贅詞。

`concepts[i][2]` 是為此新增的第三個元素。清單只在教學卡顯示、永遠不會變成
選項——這同時解決兩件事：句子讀不完，以及選擇題出現 200 字以上的選項。

### 154 堂全部改寫完成

| 指標 | 前 | 後 |
|---|---|---|
| 總字數 | 132,806 | **97,257**（−27%） |
| 句長中位數 | 30 字 | **19 字** |
| 最長句 | **285 字** | **101 字** |
| 超過 40 字的句子 | 31% | **5%** |
| 概念說明中位數 | 51 字 | **23 字** |
| 概念說明最長 | **257 字** | **54 字** |
| 抽出的清單 | 0 | **469 組 / 1,432 條** |

做法是開 9 個子代理平行處理，一個代理擁有一個課程檔案（這也是把單一
notes.js 拆成 15 個檔案的理由——同一個檔案多人改一定互相覆蓋）。

**驗證不採信代理自報的數字。** 基準用 `git show HEAD:` 取出動手前的版本，
在瀏覽器裡把兩邊都 parse 成真正的物件逐堂比對：概念數量與順序、元素型別、
出題門檻、`source` 保留、`tldr` 齊備。這一點很重要——有三個代理回報它們的
暫存檔被其他代理同名檔覆蓋，其中一個第一次量到的「改寫前」數據是別人的課程。

### 規則式改寫會踩到的三個坑

驗證過程抓到的都不是「寫得不好」，而是**規則被照字面執行**的後果：

1. **操作型字面值被當成贅詞刪掉。** 我寫了「刪掉出處」，代理就把
   `ringling.libguides.com/ai/framework`（練習必須的下載位置）、`max_tokens`
   （開發者課程的參數名）、`claude.ai`（註冊位置）一起刪了。寫了一支檢查器
   比對「原文有、改寫後整堂都找不到」的識別碼型字串，才抓出這 4 處。
2. **字數上限逼出假步驟。** 我寫了「workflow 每步 ≤22 字」，於是出現
   `按 Edit 編輯。`、`並指定發布狀態。` 這種句子後半截。Goodhart 定律的實例：
   給了數字，就用切句子的方式命中。修正後的規則是「每一步必須是完整可執行的
   動作，字數次要」，26 堂的步數從 9–12 步回到 5 步。
3. **細步讓排序題變成罰寫。** 有 7 堂的 workflow 一度長到 9–12 步，而排序題會
   把全部步驟丟給使用者排。修在出題器：超過 `QUIZ.orderMax` 就取一段連續區間
   來考，題目註明整個流程共幾步。

同時也修掉一個出題器的真 bug：`distractors()` 只按 `lessonId:idx` 去重，
沒有按文字去重。`Delegation 委派` 這個概念標題在三門課裡一字不差，所以偶爾
會有兩個同名概念同時被選成干擾項，那一題就出現兩個一模一樣的選項。
機率約 1/9000，是靠跑 120 輪 × 154 堂（18,480 次生成）才穩定抓到的。

### 間隔重複

答對一次熟練度 +1、答錯 −1，下次到期時間由熟練度決定：**1 / 3 / 7 / 16 / 35 天**。答錯的題目退一階並隔天再問。

熟練度在複習頁是攤開來看的（哪一題、第幾階、什麼時候再問），刻意不做成黑盒子。

**沒有愛心、沒有失敗狀態。** 答錯只是把題目排到後面再問一次。對成年專業學習者來說，失敗重來的機制只會讓人放棄，而不會讓人學得更好。

## 本機執行

沒有建置流程，也不需要 Node 或 Python：

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

然後開 http://localhost:8080 。換 port：`-Port 3000`；不要自動開瀏覽器：`-NoBrowser`。

`serve.ps1` 用 `TcpListener` 起一個約 30 行的靜態伺服器（不是 `HttpListener`，因為那個通常要管理員權限或 `netsh http add urlacl` 保留）。VS Code 的 Live Server 也可以。

**必須用 http(s) 開，不能直接雙擊 `index.html`。** ES modules 在 `file://` 下會被 CORS 擋掉。

## 內容範圍與一個必須講清楚的限制

官方全部 **20 門課、444 堂課**。其中 **5 門是純影片課，佔 290 堂**（Building with the Claude API、Claude with Amazon Bedrock、Claude on Google Cloud、MCP 入門與進階）——官方課堂頁只有影片，沒有隨附文字教材，也沒有字幕或逐字稿可以整理。

與其產出憑空推測的內容，本站對這 290 堂：

- **不寫筆記**，改為在地圖上收成 45 個章節節點（否則雲端島會有 176 個節點）
- 節點用**虛線路段**與**影片圖示**標示，路段標題寫明「官方影片路線」
- 完成是**自我回報**，用空心勾而不是實心勾，旁邊明寫「本站無法驗證，這是你自己的紀錄」
- 每堂 4 XP，而有筆記的課堂是 10 XP

這三個視覺訊號是承重結構不是裝飾。少了它們，地圖就會開始暗示本站涵蓋全部 444 堂的教學內容。

## 設計決定

**為什麼沒有建置流程。** 不帶 `defer` 的 classic `<script src>` 在解析期同步依序執行，而 `<script type="module">` 隱含 defer、在文件解析完才跑。所以模組開始執行時 `window.ACADEMY_*` 早已就緒——590 KB、7,474 行的資料檔一行都不用改，也不必冒著在 401 KB 資料檔裡打錯字的風險去轉成 ESM。部署就是 `git push`。

**XP 是推導值不是累加值。** 每次狀態變動就從「已完成的課堂集合 + 筆記 + 徽章」整份重算。取消完成時 XP 自動退回、不必寫反向邏輯；兩台裝置合併時不會把同一堂課算兩次；調整 XP 規則之後所有人的數字立刻正確，不需要資料遷移。

**為什麼完成偵測是「翻到最後一張 + 按一下」。** 「捲到底」在這份資料上是壞的——290 堂純影片課沒有內容可捲，頁面短到一載入就等於捲到底，會誤判 65% 的課完成。「停留時間」也不行，93 堂的 Vertex 和 15 堂的基礎課無法共用門檻。

**全站零 `innerHTML`。** 本站會渲染兩種完全由使用者控制的字串——他們自己寫的筆記，以及（Phase 2 之後的）Google `displayName`，後者可以是 `<img src=x onerror=...>`。一旦流進 `innerHTML` 就是 `finianex.github.io` 上的儲存型 XSS，而那個來源與 Firebase Auth 的 token 儲存同源。`app/dom.js` 提供 `el()`，讓任何人都沒有理由去碰 `innerHTML`。

**彩色不當文字色。** `#58CC02` 對白底只有約 2.3:1、`#FFC800` 約 1.7:1，都遠低於 AA 的 4.5:1。所以彩色只用於填色、邊框與進度條；文字一律深灰（11:1），彩底上用白色，需要彩色文字時走 `--*-text` 那一組（全部實測 ≥4.9:1）。

**localStorage 一律 `aaq:v1:` 前綴。** GitHub Pages 上所有 repo 共用 `finianex.github.io` 這一個來源，localStorage 是整個網域共享的，沒有前綴就會和其他專案互撞。

## 部署

正式站是 **Firebase Hosting**（專案 `claude-elearning`），推到 `main` 就由 `.github/workflows/firebase-hosting.yml` 自動部署，不需要本機裝 firebase CLI。設定散在三個檔案：`firebase.json`（站台內容與快取標頭）、`.firebaserc`（專案別名）、workflow（觸發與憑證）。憑證放在 GitHub secret `FIREBASE_SERVICE_ACCOUNT`，是一組只有 Firebase Hosting Admin + Firebase Viewer 兩個角色的 service account JSON。

**為什麼不是 GitHub Pages。** Pages 跑得起來（站台零絕對路徑，`/` 和 `/子路徑/` 都可以），但 `signInWithRedirect` 在 Pages 上對限制第三方儲存的瀏覽器（Safari 16.1+、Firefox ETP strict、Chrome 限制第三方 cookie）是壞的——流程需要從 `<project>.firebaseapp.com` 的第三方情境讀狀態，官方修法是把 `/__/auth/**` 反向代理到自己的網域，而 Pages 做不到。Firebase Hosting 天生就提供那條路徑，而且 `web.app` / `firebaseapp.com` 預設就在 Auth 的 authorized domains 裡。根目錄的 `.nojekyll` 是 Pages 時期留下的，對 Firebase 無作用但也無害。

**快取刻意設成 `no-cache`。** 這個專案沒有建置流程，檔名固定（`content/notes/claude-101.js` 永遠是這個名字），所以不能用長快取——課文改了卻讓使用者卡在舊版是這裡最糟的失敗模式。`no-cache` 仍然走 ETag 重新驗證，沒改就回 304，成本很低。圖檔類才給 1 天。

## 登入與同步

Google 登入是**可選的**。未登入時全站功能完整，資料存在 localStorage；登入只是把儲存從「這台裝置」升級成「這個帳號」。地圖是首頁的主體，不能要求先登入才看得到。

**匿名訪客為 Firebase 下載零位元組。** SDK 走動態 `import()`，滑到登入按鈕上才預熱。實測未登入載入首頁時 `firebasejs` 的請求數是 0。

**用 popup 不用 redirect。** `signInWithRedirect` 需要從 `<project>.firebaseapp.com` 的第三方情境讀狀態，在限制第三方儲存的瀏覽器會失敗。popup 的代價是必須由手勢觸發，而 SDK 延遲載入的 `await` 會切斷手勢鏈——所以 `pointerenter` / `focus` 時就先預熱。

**雲端的 `game.xp` 存的是歷史最高值，不是當前值。** 安全規則要求 XP 單調遞增，但使用者取消勾選一堂課、或把筆記清空，都會讓推導出的 XP 變小。照實寫入會被規則拒絕，而 `writeBatch` 是原子的——同批的進度與筆記會一起失敗，一次取消勾選就讓帳號從此同步不了。畫面上的 XP 一律由 `gamify.derive()` 即時重算，雲端那個值從來沒有被讀回來顯示，所以存高水位不影響任何行為。

**合併的原則是「寧可附加也不丟棄」。** 兩台裝置改同一篇筆記時，較新的放上面、較舊的接在下面並標明來源時間。默默弄丟使用者手寫的筆記是這個產品最糟的失敗模式；使用者兩秒就能刪掉多餘那段，但刪掉的內容救不回來。進度取 max（完成是單調的）、造訪次數相加、XP 從合併後的狀態重算而不是相加。`app/merge.js` 是純函式，22 項合併行為有瀏覽器內的驗證腳本可跑。

**Firestore 規則手動貼。** `firestore.rules` 在版控裡，但 `action-hosting-deploy` 只部署 hosting，不碰規則——改了規則要自己貼進 Console 發布。

## 隱私

未登入時：沒有登入、沒有分析工具、沒有第三方請求，進度與筆記只存在你自己瀏覽器的 localStorage 裡。

登入後：進度、筆記、角色設定存在 Firestore 的 `users/{你的 uid}` 底下，只有你自己讀得到（安全規則不給 `list`，所以「列出所有使用者」在協定層面就不可能）。專案有連結 Google Analytics，但本站**不載入** `firebase-analytics`，`app/config.js` 也刻意沒有收 `measurementId`，所以不會有任何量測請求或 cookie。

登出預設保留這台裝置上的進度（不敏感、離線仍有用，你可能只是想以匿名身分繼續讀）；另有「登出並清除這台裝置的資料」清掉全部 `aaq:v1:*` 並清空 IndexedDB。「我的角色」頁可以把資料匯出成 JSON。
